## 校验发现

1. **代码区分大小写。** `h30182.CSI` 返回0条，`H30182.CSI` 返回187条。扫描据此统一请求代码为大写，重查此前小写空结果，保留两种原始回执；库内代码不改，后缀和收益版本不替换。
2. **对照样本完全一致。** 沪深300 HTTP 与 MCP 返回的300行完全一致，8月权重与缓存的中证官方文件逐项一致。该对照不计入523个缺口。
3. **深成指R具备更强完整性证据。** Tushare的500个证券代码与同日国证官方文件完全一致，每条权重差异均在官方两位小数的舍入范围内。官方公布数值合计100.13%，原适配因超过0.1个百分点阈值而拒绝；Tushare较高精度数值合计99.9993%，可作为后续接入的首个校验样本。
4. **创业板综暂不计为可补齐。** Tushare返回1356条、合计约100%，官方文件有1357条；缺少绿控传动 `301655.SZ`，官方显示权重0.00%。这不是从接口取得了该证券的完整权重，不能自行添加零值或用合计100%证明名单完整。
5. **两个中国互联网指数需证券身份映射。** `H11136.CSI`、`H01136.CSI` 各返回48条，但各有11个美股成分只提供ATHM、PDD等无交易所后缀代码；暂从候选中扣除，不自行猜后缀。

全部407份非空回执均没有空权重或重复证券，权重总和与100%的差距在0.1个百分点以内。上面3个问题指数说明，这些数值检查不能单独证明完整性。最大单个响应为5191行，不能照搬项目另一个接口的固定行数上限推断截断与否。

## 接入判断

[Tushare官方说明](https://tushare.pro/document/2?doc_id=96)将 `index_weight` 定义为月度成分权重，来源为指数公司公开数据。当前实测支持将该代理作为常规指数缺口的重要来源，Wind继续承担独有或其他来源缺失的指数；这里测试的是用户指定代理，不等同于直接验证Tushare官方账号权限或代理的数据授权条款。

HTTP和MCP均已实取成功。MCP列出283个工具，只实测了其中的 `index_weight`，不能把工具清单当作283项均已验证。MCP部分接口参数使用 `symbol`，与HTTP的 `ts_code` 有差异，应按各自契约调用。Python环境没有安装Tushare包，本次未单独测试SDK；用户提供的SDK写法最终也指向该HTTP服务，不构成第三个独立数据源。

本轮串行请求、复用缓存，未收到权限、额度或限流错误；这不能证明接口不限速。HTTP权重回执耗时中位数约0.8秒，未做并发或极限速率测试。

生产接入仍需：新增明确的Tushare来源及完整性校验依据；补齐证券名称和必要的市场身份；处理名单遗漏、响应截断与独立总数核验；保留实际日期、原始数值、回执和冲突检查。现有写入函数仅接受Wind/中证/国证，不能给代理数据套用Wind或官方直取标签。
