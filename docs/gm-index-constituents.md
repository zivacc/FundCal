# Parallels 掘金 SDK 指数成分实测

核验时间：2026-09-29。使用用户已授权复用的既有 Quant3 模板 Token，只读调用 gm 3.0.186；没有运行策略、回测、下单或改写正式数据库。原文与汇总在忽略目录 `data/wind/gm-probe-20260928/`（目录沿用首次探针日期）。

## 结果

调用 `stk_get_index_constituents(index, trade_date=None)`，2026-09-29早间返回的最新日期均为2026-09-28：

| 指数 | SDK代码 | 不重复成分数 | 权重原值合计 | 结论 |
| --- | --- | ---: | ---: | --- |
| 沪深300 | SHSE.000300 | 300 | 0 | 全部权重为0，只能作为名单 |
| 创业板指 | SZSE.399006 | 100 | 0.999999 | 全部非空且非零，可提供完整权重 |
| 上证50 | SHSE.000016 | 50 | 1.000010 | 全部非空且非零，可提供完整权重 |
| 科创50 | SHSE.000688 | 50 | 1.000010 | 全部非空且非零，可提供完整权重 |
| 深证成指 | SZSE.399001 | 500 | 0 | 全部权重为0，只能作为名单 |
| 中证500 | SHSE.000905 | 500 | 0 | 全部权重为0，只能作为名单 |

另查 `SZSE.399006, trade_date='2026-08-31'`，返回100个成分，权重合计1.000001。与国证官方同日完整文件对照：代码100/100相同，SDK权重乘100并四舍五入到两位小数后，100/100相同。因此SDK的 `weight` 是小数比例，入本库 `weight_pct` 时需要乘100。

实测单次调用约0.06–0.44秒，仅7次串行样本，不代表大批量吞吐、无限频率或全市场覆盖。不能把全零当作有效持仓，也不能用返回的市值字段自行推算指数权重。[东财同系列说明](https://emquant.18.cn/help/doc/python/python_select_api_stock.html)确实提示部分指数权重不可用；深证成指实测也全零，故应按每个指数实际响应验证，不能只按发行商推断支持范围。公版gm与券商版权限/额度不能直接等同。

本机还存在 `stk_get_index_history_constituents(index, start_date='', end_date='')`，已核验函数签名但未调用范围历史接口。旧 `get_constituents` 和 `get_history_constituents` 被SDK标为弃用。历史能力目前只证明一个指定日期可用，不代表任意年份都有数据。

## 运行条件

- Mac→Windows共享目录与命令桥可用，Windows Python位置见 [Quant3实测记录](/Users/ziva/projects/Quant3/research/tooling-assessment.md)。
- 掘金终端必须运行且数据服务可连接；仅有Token和SDK安装不够。终端未运行时，查询报 `GmError status=1001: 无法连接到终端服务`。
- Mac的Parallels应用包装入口本轮未成功启动终端；通过 `prlctl exec 'Windows 11' --current-user` 在登录用户会话中启动已有 `goldminer3.exe` 后成功，取数也在同一用户会话执行。
- 虚拟机原启用了 `Pause idle: on`，后台会自动暂停。本轮临时关闭以完成探针，结束已恢复为on。无人值守同步需要明确处理VM运行状态和终端就绪，不能只执行Python命令。
- Token只在虚拟机内读取并传给SDK，没有打印或另存。首次读取曾因缺少明确授权被自动审核拒绝；用户回复“允许复用”后才执行。

## Wind 既有快照日期疑点

SDK校验额外发现：库内标为2026-09-28的Wind上证50快照，与官方2026-08-31的50行权重逐行完全一致；创业板Wind同标签快照与官方8月末权重也在舍入精度内一致，却与SDK9月28日权重明显不同。

对全部现有重叠快照只读比对，共发现10份这种日期疑点：

- 7份与官方8月31日的成分及权重逐行完全一致：000010.SH、000016.SH、000510.SH、399975.SZ、399986.SZ、930050.CSI、931151.CSI。
- 3份成分全部一致，权重差异不超过0.005个百分点，与国证两位小数的公开精度吻合：399004.SZ、399006.SZ、399673.SZ。

这表明先前将Wind返回“日期”直接认作权重实际日期的结论不充分，可能混淆查询截止日和权重生效日。**上述Wind快照不能当作已经核实的9月28日权重。** 其余11份尚无同日官方样本作独立日期核验，也不能因本轮未发现冲突就认为日期已验证。

本轮没有根据相似性擅自改写日期或覆盖数据；回执原文保留。现有覆盖报告仍按数据库的 `as_of_date` 排序，因此其Wind最新日期与优先级不能作为新鲜度已验证的证明。正式接入下一阶段应先增加独立的日期可信状态/隔离与裁决，再将通过校验的SDK快照按独立来源写入；不能让疑似旧数据仅凭较新日期标签压过官方文件。

## 接入判断

该SDK能承担**已验证支持指数的日频权重来源**，并提供部分历史日期；名单覆盖大于权重覆盖。官方完整文件仍用于公开全量与交叉验证，Wind保留独有指数/缺口但须补日期核验。现阶段是探针验证完成，尚未建立正式SDK批量同步器。
